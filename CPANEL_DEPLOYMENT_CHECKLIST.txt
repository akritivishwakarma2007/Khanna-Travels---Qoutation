5. DATABASE REQUIREMENTS
--------------------------------------------------------------------------------
* Database Type: MongoDB (NoSQL document database).
* Hosting Model: **EXTERNAL HOSTING via MongoDB Atlas Cloud**.
  - cPanel does NOT need to run or install MongoDB server locally!
  - Connection is handled remotely through Mongoose over TLS.
* Connection String Format:
  `mongodb+srv://<username>:<password>@<cluster>.mongodb.net/<database>?retryWrites=true&w=majority`
* Connection Requirements:
  - Outbound TCP Port **27017** must be open on the cPanel hosting server's firewall.
  - MongoDB Atlas IP Access List (Network Security):
    You MUST whitelist the public outbound IP address of your cPanel server in the
    MongoDB Atlas dashboard (or allow `0.0.0.0/0` with strong password credentials).
* Schema & Collections:
  - `companies`: Underwriter profiles, embedded plan configurations, and rate grids.
  - `quotes`: Saved client quotations and search metadata.
  - `visalinks`: Official embassy and visa portal directory.
* Migrations & Initial Setup:
  - Automated: Run `node seed.js` from `server/` to seed initial rate tables if empty.
  - Resilient: The application operates gracefully if collections are already populated.

* SMART SAME-ORIGIN API URL DETECTION (NOW CONFIGURED):
  `js/api.js` has been configured to automatically detect and support cPanel deployments:
  ```javascript
  let activeBaseUrl = IS_LOCAL
    ? LOCAL_BACKEND_URL
    : (typeof window !== 'undefined' && window.location && window.location.origin && !window.location.origin.includes('vercel.app')
        ? window.location.origin
        : RENDER_BACKEND_URL);
  ```
  - **Local Development**: Points automatically to `http://localhost:3000`.
  - **cPanel Deployment**: Points automatically to your custom live domain (`window.location.origin`).
  - **Fallback**: Automatically falls back to the cloud backup backend if the primary host is temporarily down.

8. FILE STORAGE & PERSISTENCE
--------------------------------------------------------------------------------
* User File Uploads:
  - File upload functionality exists in `server/routes/rates.js` for importing
    CSV/Excel rate sheets.
  - Implementation detail: Multer uses `multer.memoryStorage()`. All uploaded CSVs
    are parsed in RAM buffer and immediately written to MongoDB.
  - Therefore, NO physical upload directory or persistent disk permissions are
    needed for uploads.
* Local JSON Fallbacks:
  - Files `server/offline-quotes.json` and `server/visa-links.json` serve as
    offline fallbacks if MongoDB disconnects.
  - Standard file read/write permissions for the user account running Node.js are
    sufficient (`chmod 644` for files, `chmod 755` for folders).
* Image / PDF Generation:
  - Client-side only. `html2canvas` renders quote cards directly in the visitor's
    browser and triggers a local file download. Zero server disk usage.

10. CPANEL COMPATIBILITY ASSESSMENT
--------------------------------------------------------------------------------
Can this project be deployed on shared cPanel hosting?

* VERDICT: **YES — FULLY COMPATIBLE WITH MINOR CONFIGURATION**, provided your
  hosting provider satisfies the following two conditions:

1. **cPanel Node.js Selector Support**:
   Your hosting plan MUST support Node.js applications (usually labeled in cPanel as
   "Setup Node.js App" or CloudLinux Node.js Selector powered by Phusion Passenger).
   *(Note: Budget PHP-only shared hosting plans that only support Apache/PHP cannot
   run the Node.js backend. If you have a PHP-only plan, see Alternative Strategy below).*

2. **Outbound Port 27017 Open for MongoDB Atlas**:
   The cPanel hosting server firewall must allow outbound connections to port 27017.
   Most modern shared hosts (e.g., Hostinger, A2 Hosting, Namecheap, Bluehost, InMotion)
   permit standard outbound database traffic.

11. STEP-BY-STEP CPANEL DEPLOYMENT INSTRUCTIONS
--------------------------------------------------------------------------------

### ARCHITECTURE OVERVIEW:
In cPanel, Node.js applications are managed by Phusion Passenger. The Node server
at `server/server.js` serves both:
  1) The `/api/*` REST endpoints
  2) The frontend static files (`index.html`, `css/`, `js/`)

### STEP 1: PREPARE FILES LOCALLY
1. Project Files:
   `js/api.js` is already configured to automatically detect your cPanel domain origin!
2. Create a clean ZIP archive of your project containing:
   - `index.html`
   - `logo.png`
   - `khanna-travels-logo.png`
   - `css/` (entire directory)
   - `js/` (entire directory)
   - `server/` (entire directory **EXCEPT** `node_modules` — do NOT zip `node_modules`)

### STEP 2: CREATE NODE.JS APPLICATION IN CPANEL
1. Log into your cPanel dashboard.
2. In the **Software** section, click **Setup Node.js App**.
3. Click **Create Application**.
4. Configure the settings:
   - **Node.js Version**: Select `18.x` or `20.x` (LTS version).
   - **Application Mode**: Select `Production`.
   - **Application Root**: Enter your project folder path (e.g., `khanna-travels`).
   - **Application URL**: Select your domain or subdomain (e.g., `quote.yourdomain.com` or `yourdomain.com`).
   - **Application Startup File**: Enter `server/server.js`.
5. Click **Create**.
6. cPanel will generate the directory and an `.htaccess` file with Passenger routing.

### STEP 3: UPLOAD PROJECT FILES
1. In cPanel, go to **File Manager**.
2. Navigate into the application root directory created in Step 2 (e.g., `/home/username/khanna-travels`).
3. Upload your ZIP archive and extract all files.
4. Verify the directory layout:
   `/home/username/khanna-travels/`
     ├── `index.html`
     ├── `css/`
     ├── `js/`
     ├── `logo.png`
     └── `server/`
           ├── `server.js`
           ├── `package.json`
           └── ...

### STEP 4: INSTALL DEPENDENCIES VIA CPANEL
1. In the **Setup Node.js App** screen in cPanel, find your application and click the **Edit** (pencil) icon.
2. At the top of the page, copy the command to enter the virtual environment (e.g., `source /home/username/nodevenv/khanna-travels/...`).
3. Open **Terminal** in cPanel (or connect via SSH):
   Paste the virtual environment command and press Enter.
4. Change directory into the server folder:
   `cd server`
5. Install production dependencies:
   `npm install --production`
6. Run the database seed script (optional, only if initializing a fresh database):
   `node seed.js`

### STEP 5: CONFIGURE ENVIRONMENT VARIABLES IN CPANEL
1. In the **Setup Node.js App** edit screen, scroll to the **Environment Variables** section.
2. Add the following variables:
   - `NODE_ENV`       = `production`
   - `MONGODB_URI`    = `mongodb+srv://<user>:<password>@quatation.tub3xrk.mongodb.net/quatation?retryWrites=true&w=majority`
   - `ADMIN_EMAIL`    = `admin@khannatravels.com`
   - `ADMIN_PASSWORD` = `khanna2026`
3. Click **Save**.

### STEP 6: WHITELIST CPANEL SERVER IP IN MONGODB ATLAS
1. Obtain your cPanel server's Shared IP Address (displayed on the right sidebar of the cPanel home page).
2. Open your [MongoDB Atlas Dashboard](https://cloud.mongodb.com).
3. Navigate to **Security** → **Network Access**.
4. Click **Add IP Address**.
5. Add your cPanel server IP address (or select `0.0.0.0/0` to allow all IP addresses with your secure username/password).
6. Click **Confirm**.

### STEP 7: RESTART APP & TEST
1. In the cPanel **Setup Node.js App** screen, click **Restart Application**.
2. Open your domain in your web browser with SSL: `https://yourdomain.com`.
3. Verify test checklist:
   - Health check: Visit `https://yourdomain.com/api/health` → Expect: `{"status":"ok","db":"connected"}`.
   - Quotation: Submit a test quote comparison → Expect instant insurer cards.
   - Admin login: Visit `https://yourdomain.com/#admin` → Log in with `khanna2026`.
   - Rate table editing: Change a rate and click "Save Changes" → Expect live MongoDB save.

ALTERNATIVE STRATEGY (If your cPanel host does NOT support Node.js):
--------------------------------------------------------------------------------
If your hosting plan is standard shared hosting without Node.js support:
1. Upload ONLY the static frontend files (`index.html`, `css/`, `js/`, `logo.png`)
   directly into your cPanel `public_html/` folder. Apache will serve it instantly.
2. Keep the backend API running on a free/low-cost Node.js cloud service
   (e.g., Render, Railway, DigitalOcean App Platform, or VPS).
3. In `js/api.js`, set `activeBaseUrl` to your cloud backend URL:
   `https://khanna-travels-qoutation.onrender.com`
4. The frontend on cPanel will communicate smoothly across CORS with the backend.
