1. Project Overview
What it is: A web app where an admin manages multiple insurance companies and their travel insurance plans/rate tables, and an agent enters a customer's trip details to instantly compare premiums across every company and plan — grouped by coverage amount (50k / 100k / 200k / 500k / 750k / 1M).

What it is not: Not a CRM, not a dashboard/reporting tool, not a customer portal. Just: manage rate data → enter a quote → compare.

Backend database: MongoDB (Atlas, cloud-hosted) — accessible from anywhere via a connection string.

3. MongoDB Database Design
Database: insuranceQuotesDB
Collection: companies
Each document represents one company, containing all of its plans, and each plan containing all of its rates — fully nested, since a company's plans/rates are only ever read/written together with that company.

Field Rules
Field	Type	Notes
companyName	String	Required, unique
planName	String	Required within a company; a company can have many
coverage	Number	One of: 50000, 100000, 200000, 500000, 750000, 1000000
region	String	"Excluding" or "Including" (USA & Canada)
ageFrom / ageTo	Number	Defines the age band for this rate row
daysFrom / daysTo	Number	Defines the days slab for this rate row
premium	Number	The price for this exact combination
currency	String	Default "INR"
No age bands or day slabs are fixed system-wide — each rate row simply states its own range, so every company can structure its bands differently if needed.

Mongoose Schema Sketch
const RateSchema = new Schema({
  coverage: { type: Number, required: true, enum: [50000, 100000, 200000, 500000, 750000, 1000000] },
  region: { type: String, required: true, enum: ["Excluding", "Including"] },
  ageFrom: { type: Number, required: true },
  ageTo: { type: Number, required: true },
  daysFrom: { type: Number, required: true },
  daysTo: { type: Number, required: true },
  premium: { type: Number, required: true },
  currency: { type: String, default: "INR" }
});

const PlanSchema = new Schema({
  planName: { type: String, required: true },
  rates: [RateSchema]
});

const CompanySchema = new Schema({
  companyName: { type: String, required: true, unique: true },
  plans: [PlanSchema]
}, { timestamps: true });

module.exports = mongoose.model("Company", CompanySchema);
Connection Setup

MONGODB_URI=your_connection_string_here

// db.js

mongoose.connect(process.env.MONGODB_URI)
  .then(() => console.log("MongoDB connected"))
  .catch((err) => console.error("MongoDB connection error:", err));
Why this structure
One companies collection is enough — no separate plans or rates collections, since they're always accessed together with their parent company.
Adding a new company = one new document. Adding a plan or rate = pushing into the relevant array. No schema changes needed for growth.
The comparison query loops through all companies → all plans → all rates, filtering by region + coverage + age range + days range, entirely on the backend via MongoDB aggregation — fast even as data grows.
Indexes (for performance once data grows)
Index on plans.rates.coverage and plans.rates.region to speed up the compare query
Unique index on companyName to prevent duplicate companies
